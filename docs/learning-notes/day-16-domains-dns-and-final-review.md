## 二、先拆开一条网址

例子：`https://personal-website-pej7.vercel.app/projects?page=2`。

| 部分 | 内容 | 作用 |
| --- | --- | --- |
| 协议 | `https` | 规定使用加密的网页通信 |
| 主机名 | `personal-website-pej7.vercel.app` | 指明访问哪个网站入口 |
| 路径 | `/projects` | 指明网站里的哪个页面 |
| 查询参数 | `page=2` | 给页面额外参数；本例请求第 2 页 |

URL（统一资源定位符）是整条地址，域名只是其中的一部分。

你之前访问 `/tools/admin` 得到 404（找不到页面），是因为程序没有这个路径，不是域名失效。正确地址是 `https://personal-website-pej7.vercel.app/admin`。修改路径时应替换域名后的内容，不要在已有路径后随意追加。

网站路径由 Next.js（全栈框架）处理，DNS 不负责区分 `/login` 和 `/projects`。

## 三、几个角色分别负责什么

| 角色 | 通俗理解 | 你的项目 |
| --- | --- | --- |
| 域名 | 对外使用的名字 | 当前使用平台分配的子域名 |
| 域名注册商 | 帮你注册和续费自有域名的服务商 | 没买域名就暂时不需要 |
| DNS 服务商 | 管理名字应该如何解析 | 当前平台地址无需你管理其 DNS |
| 网站托管平台 | 运行和提供你的网站 | Vercel |
| 应用程序 | 决定页面、业务处理与访问控制 | Next.js 项目 |
| 后端服务 | 保存数据、提供认证与数据库权限 | Supabase |

注册商和 DNS 服务商可以是同一家，也可以不是。买了域名不等于买了服务器，也不等于网站自动上线。绑定新域名也不会自动搬迁数据库。

当前地址本身已经是可以使用的域名，不是“没有域名”。自购域名的主要价值是更容易记忆、形成自己的品牌，并能在迁移托管平台时继续保留名字。Vercel 提供的地址足以完成本课。[平台域名说明](https://vercel.com/docs/domains/working-with-domains)

## 四、DNS 记录怎么看

DNS 保存的是结构化记录，不是一整条网页地址。

| 记录类型 | 含义 | 常见用途 |
| --- | --- | --- |
| A | 名称对应 IPv4（第四版网络协议）地址 | 将主机名指向一个网络地址 |
| AAAA | 名称对应 IPv6（第六版网络协议）地址 | 支持 IPv6 访问 |
| CNAME | 一个名称是另一个名称的别名 | 子域名指向托管平台提供的目标 |
| TXT | 文本记录 | 验证域名控制权等 |
| MX | 邮件服务器记录 | 决定邮件投递位置 |
| NS | 权威名称服务器记录 | 指明由哪些服务器负责解析 |

`@` 在很多 DNS 控制台中表示当前域名本身，例如 `example.com`；`www` 表示 `www.example.com`。具体输入方式仍要看服务商说明。

TTL（缓存有效时间）表示解析结果可缓存多久。改完记录后，不同地方可能暂时看到不同结果，不能用“一定立即生效”判断成功与否，也不要反复修改来碰运气。[DNS 记录基础说明](https://www.cloudflare.com/learning/dns/dns-records/)

重要区别：CNAME 不是网页重定向。它参与解析，通常不会让浏览器地址栏改成目标名称；Redirect（重定向）是网站返回响应，告诉浏览器访问另一个网址。

## 五、路线 A：不买域名也能做的实际练习

### 任务 1：记录当前正式入口

打开 Vercel 项目中的 Domains（域名）区域，确认当前入口为 `personal-website-pej7.vercel.app`。本次只查看，不删除或改名。

区分“项目的稳定访问地址”和“某一次部署的独立地址”。分享网站时优先使用已确认的正式入口，不要随意复制很长的单次部署链接。

### 任务 2：查询解析结果

在 PowerShell（命令行环境）执行：

```powershell
Resolve-DnsName personal-website-pej7.vercel.app -Type A
```

解释：`Resolve-DnsName` 查询名称解析；后面是主机名，不带 `https://` 或 `/admin`；`-Type A` 指定查询 IPv4 地址记录。

这个命令只查询，不修改本机、平台或域名记录，会产生一次网络查询。预期得到记录类型和地址，可能同时展示别名链。地址可能不止一个，也不要求与别人的结果完全相同。[微软命令说明](https://learn.microsoft.com/en-us/powershell/module/dnsclient/resolve-dnsname)

如果命令不可用，可以用系统常见的查询工具：

```powershell
nslookup personal-website-pej7.vercel.app
```

它同样只查询。出现“非权威应答”通常表示答案来自递归解析服务器，而不是错误。若超时，记录完整错误，不能仅据此判定云端程序坏了。

只查询成功不能证明页面正常、证书有效或权限正确，也不要把查询到的共享平台地址直接当成自有域名的配置值。

### 任务 3：检查 HTTPS

打开正式网址，在浏览器的站点信息中查看连接和证书信息。不同版本浏览器图标不同，不一定显示小锁。

预期：没有证书警告，证书适用于访问的主机名，并在有效期内。

HTTPS 使用 TLS（传输层安全协议）加密浏览器与服务端之间的通信，证书帮助确认连接的主机身份。它不等于管理员权限，也不能代替数据库 RLS（行级安全）。钓鱼网站也可能有合法证书，所以“有证书”不等于“业务可信”。

不要为了继续操作忽略证书警告并提交账号密码。Vercel 会为符合验证条件的域名尝试自动签发证书，DNS 配置和域名验证需要先正常完成。[证书说明](https://vercel.com/docs/domains/working-with-ssl)

完成这三个任务后，没有自购域名的同学直接进入第八节最终验收。路线 B 阅读理解即可，标记“未操作”，不是学习失败。

## 六、路线 B：已有自有域名时的可选绑定

本节里的 `example.com` 只是示例，不要实际绑定它。只有你拥有或获得管理授权的域名才能操作。

### 修改前的准备

1. 确认当前网站在哪个 Vercel 项目：本次成功部署截图中的项目是 `personal-website-pej7`。
2. 确认域名目前是否用于其他网站或邮箱。
3. 保存当前解析记录截图或导出备份，记录旧值与 TTL。
4. 如果已有网站，不直接替换根域名；先选择一个未占用的子域名试验，例如 `portfolio.你的域名`。
5. 不购买新服务、不转移域名、不修改整组名称服务器作为默认操作。

### 绑定步骤

1. 在正确项目的 Domains（域名）区域添加目标主机名，不带协议和页面路径。
2. 查看平台给这个域名显示的记录类型、名称和目标值。
3. 到当前实际生效的 DNS 服务商控制台，填写平台要求的记录。
4. 若提示需要验证所有权，按平台要求添加对应 TXT 记录。
5. 等待平台确认配置和证书状态，实际用新地址打开网站。

根域名常用 A 记录，子域名常用 CNAME；目标值以你当前项目界面为准，不照搬网上的固定 IP（网络地址）或别人的 CNAME。修改会改变真实访问流向，保存前必须再次核对目标。[添加域名官方步骤](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

同名旧 A、AAAA 或 CNAME 可能产生冲突，但不要把整张记录表清空。MX 和邮件相关 TXT 可能服务于邮箱，误删会影响邮件。遇到不认识的记录先停下来确认用途。

如果注册商与 DNS 服务商不同，在注册商提供的“非生效 DNS 区域”修改可能没有效果。更换 NS 属于整域解析管理迁移，需要完整迁移原记录；不是简单绑定一个网站的必需步骤。

### 根域名和 www 要统一吗？

`example.com` 和 `www.example.com` 是两个不同主机名。可以选一个作为主要地址，让另一个单向重定向过去。两边都需要正确配置，避免 A 跳 B、B 又跳 A 的循环。

首次学习可以只绑定一个子域名，不必一次配置所有入口。只有新入口、HTTPS 与登录都确认正常后，再考虑旧入口如何保留或重定向。

## 七、更换网站域名后哪些配置要关注

### Supabase 地址不要换成网站地址

`NEXT_PUBLIC_SUPABASE_URL` 仍然是 Supabase 后端项目地址。网站换门牌，不等于数据库换位置，其他密钥与管理员标识也不会因此需要替换。

### 站点地址与认证回调

如果以后采用自有域名作为正式入口，检查 Supabase 的 Site URL（默认站点地址），以及实际实现的认证流程所需的 Redirect URLs（允许跳转地址）。生产环境尽量使用准确地址，不允许任意域名跳转。

本项目当前使用邮箱密码登录，登录后的 `/admin` 跳转由代码处理；没有实现第三方登录回调就不必凭空配置 `/auth/callback`。Site URL 主要涉及确认邮件、重置密码等默认跳转场景，不是所有登录问题的通用修复办法。[Supabase 跳转配置说明](https://supabase.com/docs/guides/auth/redirect-urls)

换主机名后，原域名的登录 Cookie（浏览器会话数据）不一定共享，新域名要求重新登录是正常现象。不要为省去登录而随意扩大 Cookie 的作用范围。

后续还应检查代码、分享信息、站点地图和邮件模板中是否写死旧网址；本课不要求添加尚未实现的搜索优化功能。若实际修改了云端环境变量，再按 Day 15 的规则重新部署。

你已经反馈 Day 15 基础检查没有问题。这里将结果结构化：能确认的写“通过”，没实际执行的写“未测试”，不需要为了填表反复操作真实数据。

| 检查项 | 标准结果 |
| --- | --- |
| 正式入口 | 打开的是自己的正确项目，HTTPS 无警告 |
| 首页、项目、工具页 | 正文和列表正常，空状态与实际数据一致 |
| 页面导航与刷新 | 正确地址能访问；不存在的路径给出找不到页面 |
| 手机宽度 | 内容可读，导航和按钮可操作，无严重横向溢出 |
| 键盘操作 | Tab（切换焦点键）可到主要链接和表单控件，焦点可辨认 |
| 登录、刷新、退出 | 管理员可登录并保持会话，退出后后台重新要求登录 |
| 普通登录用户 | 不能管理或写入，即使知道后台地址也不行 |
| 私有项目 | 未登录用户在列表、详情正文、标题中均不可见 |
| 公开切回私有 | 无痕窗口重新请求后不可见 |
| 数据接口权限 | 匿名身份无法读取私有项目及其亮点、标签关联；非管理员写入被拒绝 |
| 编辑与删除 | 仅用自己新建的测试记录；结果正确且无误删 |
| 日志和秘密 | 无持续应用报错，不输出密码、令牌、完整会话数据 |

无痕窗口适合测试未登录状态，但不等于普通登录用户，后者需要单独身份。只检查按钮不够，沿用 Day 14 的真实身份数据权限测试步骤。

新建测试记录不要包含真实秘密；删除测试记录可能不可恢复，不删除原有项目。私有不是保密资料保险箱：已经公开并被下载的内容无法追回。

当前已知边界：首页收藏工具来自静态数据，后台改工具后它可能不跟着变；项目公开查询则已连接数据库。如果这不符合你下一阶段需求，把它列为后续功能，不误判成域名问题。

## 九、排查顺序：先确定是哪一层

| 现象 | 优先检查 |
| --- | --- |
| 域名无法解析 | 拼写、实际 DNS 服务商、记录和查询错误 |
| 证书不匹配或过期警告 | 当前主机名、平台验证与证书状态；不要提交密码 |
| 出现别人的网站 | 域名绑定到哪个项目、解析目标与重定向 |
| `/tools/admin` 返回 404 | 地址路径，应改为 `/admin`，不用改 DNS |
| 首页正常、登录失败 | 认证配置、账号、会话与运行日志 |
| 平台安装报锁文件错误 | 修复并提交依赖锁文件，不改数据库密钥 |
| 本地通过、云端仍失败 | 云端实际提交编号、安装和构建命令、环境变量范围 |
| 某个网络打不开 | 记录时间、网络和错误，对照另一网络；不要直接推断代码坏了 |

此前的两次错误就是定位练习：锁文件问题属于依赖安装层；错误的后台地址属于应用路径层。用它们练习“看到具体证据，再改对应配置”。

## 十二、自测题与标准答案

1. **域名和完整网址有什么不同？**  
   答：域名是网址里的主机名部分，完整网址还可以包含协议、路径、查询参数。
2. **`/tools/admin` 的 404 能靠改 DNS 修好吗？**  
   答：不能，DNS 不决定应用页面路径；应访问已经实现的 `/admin`。
3. **购买域名后网站就会自动运行吗？**  
   答：不会，仍需要网站托管、应用部署及域名指向配置。
4. **A 与 CNAME 的区别是什么？**  
   答：A 对应 IPv4 地址，CNAME 对应另一个主机名。
5. **能照抄别人的 Vercel 解析目标吗？**  
   答：不能，以当前项目和域名界面提供的目标为准。
6. **CNAME 会自动改变浏览器地址栏吗？**  
   答：不会当然改变，它是解析别名；改变访问网址通常靠重定向。
7. **为什么不能清空所有 DNS 记录再配置？**  
   答：已有记录可能服务其他网站、邮箱或所有权验证，清空会破坏这些服务。
8. **HTTPS 能保证普通用户不能修改数据库吗？**  
   答：不能，它保护传输连接；访问权限需要服务端校验和数据库规则。
9. **新域名要求重新登录一定是错误吗？**  
   答：不是，浏览器会话数据受主机名等作用范围限制。
10. **网站换域名，需要更改 Supabase 项目地址吗？**  
    答：不需要，除非后端项目真的更换。网站入口和数据库入口不是一回事。
11. **没有自购域名能完成 Day 16 吗？**  
    答：可以，使用现有平台地址完成查询、HTTPS 检查、验收和交付记录即可。
12. **“我能登录”是否代表权限完全正确？**  
    答：不是，还要验证普通用户和匿名用户被正确限制，包括直接数据访问。
13. **部署回滚会撤销数据库删除吗？**  
    答：不会，恢复代码和恢复数据是两件事。
14. **为什么要记下未测试项？**  
    答：避免把猜测当作验收证据，让后续工作有明确边界。
