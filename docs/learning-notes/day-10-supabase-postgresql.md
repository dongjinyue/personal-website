## 二、为什么改用 Supabase

Supabase 不是一种新数据库。每个 Supabase 项目都提供一个完整的 PostgreSQL 数据库，并在它周围提供：

- Auth（身份认证）；
- 自动生成的 Data API（数据接口）；
- RLS（行级安全策略）；
- Storage（文件存储）；
- Dashboard（网页管理界面）；
- Migration 和 CLI 工具。

它适合本项目后续路线：

```text
Day 10 数据库
↓
Day 11 管理员登录
↓
Day 12 管理后台
↓
Day 13/14 CRUD 与权限
↓
Day 15 部署
```

与本地 SQLite 相比，Supabase 数据库可以被部署后的 Next.js 应用访问，不依赖某一台电脑上的本地文件。

## 三、Supabase 中真正使用的 PostgreSQL

PostgreSQL 是成熟的关系型数据库。Day 9 学过的概念全部继续适用：

- Table（表）；
- Row（行）；
- Column（列）；
- Primary Key（主键）；
- Foreign Key（外键）；
- UNIQUE（唯一约束）；
- CHECK（检查约束）；
- Index（索引）；
- JOIN（连接查询）；
- Transaction（事务）。

Supabase 不会替你取消数据库设计工作，它只是托管 PostgreSQL 并提供额外服务。

Project Ref 不是数据库密码。

## 五、为什么仍然需要 Migration

可以在 Dashboard 里直接点击创建表，但这样结构变化只存在远程项目中，Git 不知道发生了什么。

正确方式：

```text
supabase/migrations/*.sql
↓ Git 记录
npx supabase db push
↓ Supabase 记录已应用版本
远程 PostgreSQL
```

Supabase 使用 `supabase_migrations.schema_migrations` 记录远程已执行迁移。CLI 会只推送尚未应用的文件。

一旦开始 Migration 工作流，后续结构变化不要直接在远程 Table Editor（表编辑器）里修改，否则本地迁移历史和远程结构会漂移。

## 七、RLS 是什么

RLS 是 Row Level Security（行级安全）。它让 PostgreSQL 根据当前用户和策略决定一行是否允许读取、插入、更新或删除。

只执行：

```sql
alter table public.tools enable row level security;
```

并不会自动允许访问。启用 RLS 后，需要 Policy（策略）明确开放操作。

Day 10 的安全模型：

```text
anon          → 可以 SELECT 公开数据
authenticated → 可以 SELECT 公开数据
任何普通用户  → 暂时不能 INSERT / UPDATE / DELETE
```

写权限将在 Day 11 确认管理员身份后加入。绝不能为了“先跑起来”创建 `using (true)` 的公开写策略。

## 八、Publishable Key 为什么可以公开

`NEXT_PUBLIC_` 变量会进入浏览器代码，因此其中内容不是秘密。

Publishable Key 的安全依赖是：

```text
Key 识别 Supabase 项目
RLS 决定这个请求实际能做什么
```

所以 Publishable Key 可以公开，但前提是每张暴露表都正确启用 RLS 和策略。

Service Role Key 会绕过 RLS，绝不能公开。Day 10 完全不需要它。

| --- | --- |
| 普通字符串 | `text` |
| 自动整数 id | `bigint generated by default as identity` |
| 布尔值 | `boolean` |
| 带时区时间 | `timestamptz` |

PostgreSQL 有真正的 boolean，不再用 SQLite 的 0/1。

## 十、更新时间 Trigger（触发器）

`created_at default now()` 只负责创建时间。普通 SQL 更新记录时，`updated_at` 不会自己改变。

建立函数和触发器：

```sql
create or replace function public.set_updated_at()
returns trigger
language plpgsql
security invoker
set search_path = ''
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;
```

```sql
create trigger tools_set_updated_at
before update on public.tools
for each row execute function public.set_updated_at();
```

这样无论以后通过后台还是 SQL 修改，数据库都会维护更新时间。

## 十二、数据库返回值为什么还要转换

数据库列使用 snake_case：

```text
is_favorite
```

现有 React 组件使用 camelCase：

```text
isFavorite
```

关联查询返回：

```ts
tool_tags: [
  { tags: { name: "代码" } }
]
```

而 ToolCard 需要：

```ts
tags: ["代码"]
```

Repository（数据访问模块）负责把数据库结构转换成页面模型。组件不应该知道关联表细节。

### 任务 7：编写 6 张表

把以下 SQL 写入刚生成的 Migration：

```sql
create table public.projects (
  id text primary key,
  slug text not null unique,
  name text not null,
  description text not null,
  long_description text not null,
  status text not null
    check (status in ('building', 'completed', 'paused')),
  cover_image text,
  project_url text,
  github_url text,
  is_featured boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.project_highlights (
  id bigint generated by default as identity primary key,
  project_id text not null
    references public.projects(id) on delete cascade,
  content text not null,
  sort_order integer not null default 0
    check (sort_order >= 0)
);

create table public.tools (
  id text primary key,
  name text not null,
  description text not null,
  url text not null unique,
  category text not null
    check (category in ('AI', '开发', '学习', '效率')),
  is_favorite boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.tags (
  id bigint generated by default as identity primary key,
  name text not null unique
);

create table public.project_tags (
  project_id text not null
    references public.projects(id) on delete cascade,
  tag_id bigint not null
    references public.tags(id) on delete cascade,
  primary key (project_id, tag_id)
);

create table public.tool_tags (
  tool_id text not null
    references public.tools(id) on delete cascade,
  tag_id bigint not null
    references public.tags(id) on delete cascade,
  primary key (tool_id, tag_id)
);
```

### 任务 15：创建服务端 Supabase Client

新建 `lib/supabase/server.ts`：

```ts
import "server-only";
import { createServerClient } from "@supabase/ssr";
import { cookies } from "next/headers";
import type { Database } from "./database.types";

export async function createClient() {
  const cookieStore = await cookies();
  const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const publishableKey =
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY;

  if (!supabaseUrl || !publishableKey) {
    throw new Error("缺少 Supabase 环境变量");
  }

  return createServerClient<Database>(supabaseUrl, publishableKey, {
    cookies: {
      getAll() {
        return cookieStore.getAll();
      },
      setAll(cookiesToSet) {
        try {
          cookiesToSet.forEach(({ name, value, options }) => {
            cookieStore.set(name, value, options);
          });
        } catch {
          // Server Component 可能无法写 Cookie。
          // Day 11 将通过请求代理统一刷新登录会话。
        }
      },
    },
  });
}
```

当前 `cookies()` 在 Next.js 16 中是异步 API，所以必须 `await cookies()`。

### 任务 16：创建工具数据库查询

新建 `lib/tool-repository.ts`：

```ts
import "server-only";
import type { Tool, ToolCategory } from "@/data/tools";
import { createClient } from "@/lib/supabase/server";

const toolCategories: ToolCategory[] = ["AI", "开发", "学习", "效率"];

function isToolCategory(value: string): value is ToolCategory {
  return toolCategories.includes(value as ToolCategory);
}

/**
 * 从数据库读取工具，并转换为现有组件使用的 Tool 结构。
 */
export async function getTools(): Promise<Tool[]> {
  const supabase = await createClient();
  const { data, error } = await supabase
    .from("tools")
    .select(`
      id,
      name,
      description,
      url,
      category,
      is_favorite,
      tool_tags(tags(name))
    `)
    .order("name", { ascending: true });

  if (error) {
    throw new Error(`读取工具失败：${error.message}`);
  }

  return data.map((row) => {
    if (!isToolCategory(row.category)) {
      throw new Error(`数据库包含未知工具分类：${row.category}`);
    }

    return {
      id: row.id,
      name: row.name,
      description: row.description,
      url: row.url,
      category: row.category,
      isFavorite: row.is_favorite,
      tags: row.tool_tags.map((relation) => relation.tags.name),
    };
  });
}
```

运行时校验不能省略。数据库虽然有 CHECK，TypeScript 生成类型通常仍把 text 表示为 string；校验后才能安全收窄为 ToolCategory。

## 十六、常见错误

### 1. 把 Service Role Key 放进 NEXT_PUBLIC

这是严重安全问题。Service Role 绕过 RLS，不能进入浏览器。Day 10 完全不用它。

### 2. 认为 Publishable Key 能代替权限策略

Key 只识别项目；RLS Policy 决定访问能力。没有正确 RLS，安全边界就不完整。

### 3. 启用 RLS 却不创建 SELECT Policy

页面会返回空数据或权限错误。启用 RLS 后所有操作默认被拒绝，需要明确只读策略。

### 4. 为了方便创建公开写策略

`for all using (true)` 会让匿名访客拥有危险权限。Day 10 只允许 SELECT。

### 5. 直接在远程 Dashboard 修改表结构

这会绕过 Migration 历史。开始使用迁移后，结构变化必须通过新 SQL 文件和 db push。

### 6. 不先 dry-run 就推送

应先预览待应用迁移和目标项目，再执行实际远程变更。

### 7. 对错误项目执行 include-seed

Seed 会写入和更新数据。执行前用 projects list 确认当前关联的是开发项目。

### 8. Seed 只使用普通 INSERT

重复执行可能产生主键冲突或重复关系。主体使用 on conflict update，关联使用 on conflict do nothing。

### 9. Seed 没使用事务

中间失败可能留下部分数据。使用 begin/commit 保证全部成功或全部回滚。

### 10. 手改 database.types.ts

它是自动生成文件，下次会被覆盖。应修改 Migration、推送，然后重新生成类型。

### 11. 在 Client Component 查询数据库管理权限

数据库写入和权限判断应在服务端执行。浏览器端不能持有高权限密钥。

### 12. 忘记 await cookies()

当前 Next.js 16 中 cookies 是异步 API。服务端 Client 工厂也必须是 async。

### 13. 直接把数据库行传给旧组件

数据库是 snake_case 和关联对象；组件需要 camelCase 和字符串数组。通过 Repository 转换。

### 14. 用 `as ToolCategory` 掩盖所有数据

类型断言不会检查运行时内容。应先验证分类是否属于合法集合。

### 15. 数据库错误时返回空数组

空数组会让真实故障伪装成“没有工具”。读取失败应抛出带上下文的错误，让错误被发现。

## 十八、自测题标准答案

### 1. Supabase 和 PostgreSQL 是什么关系？

标准答案：Supabase 为每个项目托管完整 PostgreSQL，并在其上提供 Auth、Data API、RLS 管理、Storage 和 Dashboard 等服务。

判断关键词：托管 PostgreSQL、附加后端服务。

### 2. 为什么不使用本地 SQLite？

标准答案：本项目后续需要部署、登录和管理后台。托管 PostgreSQL 能被部署后的应用访问，Supabase Auth 与 RLS 还能继续支持身份和权限。

判断关键词：部署可访问、登录、权限。

### 3. Migration 解决什么？

标准答案：它以有顺序、可提交 Git 的 SQL 文件记录数据库结构变化，使不同环境可以应用一致结构，并能追踪哪些变化已经执行。

判断关键词：版本历史、环境一致、可追踪。

### 4. 为什么不能直接改远程表？

标准答案：直接修改绕过本地 Migration 和远程迁移历史，导致代码仓库描述的结构与真实数据库不一致，后续 db push 可能冲突。

判断关键词：绕过历史、结构漂移、推送冲突。

### 5. 两种 Key 有什么区别？

标准答案：Publishable Key 用于普通客户端，实际权限受 RLS 限制；Service Role Key 拥有高权限并可绕过 RLS，只能保存在可信服务器秘密环境中。

判断关键词：受 RLS 限制、绕过 RLS、高权限秘密。

### 6. 为什么 Publishable Key 可以公开？

标准答案：它用于标识项目而不是授予无限权限，真正的数据访问由 RLS Policy 控制。因此可以进入浏览器，但仍必须正确配置 RLS。

判断关键词：项目标识、RLS 决定权限。

### 7. 什么是 RLS？

标准答案：RLS 是 PostgreSQL 的行级安全机制，根据当前角色、用户和策略决定哪些行允许执行哪些操作。

判断关键词：行级、角色用户、操作控制。

### 8. 为什么还需要 Policy？

标准答案：启用 RLS 后默认拒绝受控访问，Policy 才明确说明某角色在什么条件下可以 SELECT、INSERT、UPDATE 或 DELETE。

判断关键词：默认拒绝、策略明确允许。

### 9. 为什么只允许 SELECT？

标准答案：公开网站需要匿名读取项目和工具，但管理员身份尚未建立。提前开放写入无法可靠区分管理员和普通访客。

判断关键词：公开读取、身份未建立、拒绝写入。

### 10. Cascade 做什么？

标准答案：删除项目或工具主体时，数据库自动删除引用它的亮点或关联行，避免留下指向不存在记录的孤立数据。

判断关键词：自动清理关联、避免孤立数据。

### 11. timestamptz 的优势是什么？

标准答案：它表示明确时间点并处理时区转换，数据库可以正确比较、排序和执行时间函数，不需要把时间当普通文字解析。

判断关键词：明确时间点、时区、可排序计算。

### 12. 为什么使用 Trigger？

标准答案：普通 SQL UPDATE 不会自动修改 updated_at。数据库触发器能让所有更新来源统一维护最新时间，而不依赖每个调用方记得设置。

判断关键词：所有更新来源、自动维护、一致性。

### 13. 为什么 Seed 使用事务？

标准答案：事务保证多条种子语句要么全部成功，要么失败时全部回滚，避免数据库停留在只写入一半的不完整状态。

判断关键词：全部成功或回滚、避免半完成。

### 14. on conflict 有什么作用？

标准答案：记录或关系已存在时执行更新或忽略，避免重复运行 Seed 产生唯一约束错误或重复数据。

判断关键词：重复执行、更新或忽略、避免重复。

### 15. 为什么不能手改生成类型？

标准答案：它由真实数据库 Schema 自动生成，下次生成会覆盖手工修改。正确流程是修改 Migration、应用数据库，再重新生成。

判断关键词：自动生成、会覆盖、从 Schema 更新。

### 16. Client 工厂为什么异步？

标准答案：Next.js 16 的 cookies() 返回 Promise，必须 await 后才能取得 Cookie Store，所以创建服务端 Client 的函数也必须是 async。

判断关键词：cookies Promise、await、异步工厂。

### 17. Repository 层做什么？

标准答案：它集中数据库查询、错误处理、运行时校验以及 snake_case/关联结构到页面 Tool 模型的转换，让组件不依赖数据库细节。

判断关键词：查询封装、转换、组件与数据库解耦。

### 18. 为什么错误不能返回空数组？

标准答案：空数组代表查询成功但没有数据；数据库失败是另一种状态。把失败伪装成空结果会隐藏故障，让用户和开发者误判。

判断关键词：空数据不等于错误、不能隐藏故障。
