# AI 基础知识与面试题库深化规范

## 1. 目标

将 Obsidian 知识库中已有的 AI 资料整编内容，从“主题概览/知识地图”提升为可从基础开始学习、也可用于技术面试复习的系统笔记。正文需要解释知识本身，面试篇需要提供可展开、能应对追问的完整答案；不能只列术语、流程名或答题提示。

目标读者是正在系统学习 Python 与 AI 应用开发的个人学习者。关键术语第一次出现时用简明中文解释；先给直观解释，再补严谨定义、公式或工程细节。

## 2. 已确认的边界

- Obsidian Vault 是笔记编辑与 Markdown 权威来源；保留现有目录和笔记，不覆盖或删除未纳入本次内容的用户文件。
- 新增或实质性改写的学习笔记沿用 Vault 模板，默认 `visibility: public`、`status: published`。
- 本次不处理视频，不推送 GitHub，不同步服务器，也不发布网站代码。
- 资料来源以之前盘点的 AI 相关目录和用户明确指出的课程资料为范围。现有索引所说的 478 是文档类路径盘点，不等于 478 份资料已逐篇阅读。每篇笔记必须区分“实际核读”“仅文件名命中”“文本不可读/待 OCR”，不能把目录盘点说成精读。
- 以重新组织、独立解释和跨资料去重为主，不大段照搬课件或题库；不复刻整份付费资料。
- 扫描件或提取失败的资料不得作为已核验事实来源；代码示例和快速变化的框架接口需标明适用版本或提醒查阅当前官方文档。
- 保留现有用户改动；不清理、不重置、不替换与本任务无关的文件。

## 3. 内容组织方案

采用“基础教材笔记 + 专题面试题库”双层结构，而不是把全部内容塞进一篇超长笔记，也不是只在现有概览上继续追加摘要。现有知识地图作为导航；基础笔记负责讲透，题库负责主动回忆和追问训练。主题之间通过 Obsidian 双链连接，重复概念只在主笔记详讲，其他位置简要回顾并链接。

### 3.1 学习专题

按由基础到工程实践的顺序覆盖：

1. Python 核心语法、数据结构、函数、面向对象、异常、文件、迭代器/生成器、装饰器、并发基础，以及 AI 项目常用的 HTTP、JSON、数据处理和 API 调用。
2. 机器学习与深度学习前置基础：数据集与特征、训练/验证/测试、损失函数、梯度下降、反向传播、过拟合与正则化、常用评估指标；只补理解大模型必需的数学和概念，不扩成泛化数学教材。
3. 大模型基础：Token 与分词、Embedding、自注意力、Transformer 结构、位置编码、因果掩码、归一化、残差、解码策略、上下文窗口与基础多模态概念。
4. 训练与微调：预训练、继续预训练、SFT、数据构造、交叉熵、优化器、PEFT、LoRA/QLoRA、偏好数据、RLHF/PPO、DPO、对齐目标与常见失败。
5. 推理、部署与性能：自回归生成、采样参数、KV Cache、显存估算、量化、批处理、吞吐与延迟、数据/张量/流水线并行、推理服务与压测。
6. Prompt（提示词）设计：指令结构、上下文示例、结构化输出、工具调用提示、注入风险、评估与迭代。
7. RAG（检索增强生成）：数据清洗、分块、Embedding、索引、稀疏/稠密/混合检索、召回与排序、重排、上下文构造、生成、引用、评测、权限过滤和故障定位。
8. LangChain 与 LangGraph：核心抽象、数据流、组件组合、状态、节点/边、条件路由、循环、持久化、恢复、人机协同、适用边界和版本差异。
9. Agent、MCP、Skill：Agent 循环、规划与执行、工具调用、记忆、权限与安全；MCP 的角色、协议参与方和交互过程；Skill 的定位、触发与边界；三者与普通工作流的比较。
10. 幻觉、评测与安全：幻觉成因与分类、事实性/忠实度、离线和在线评测、人工评测偏差、基准局限、拒答、提示注入和风险缓解。
11. 多模态基础：图像、语音、视频等输入输出路径、常见模型组件和评估注意事项；不声称超出可核读来源的细节。
12. Dify/Coze 与应用案例：工作流与 Agent 配置、知识库接入、工具节点、发布调试、案例拆解；平台界面与 API 属易变内容，需注明核对版本。

### 3.2 面试题库

基础原理和工程专题分别配套可检索的面试题库，至少覆盖 Python、机器学习/深度学习基础、大模型基础、训练微调、推理部署、RAG、LangChain/LangGraph、Agent/MCP/Skill、幻觉评测与多模态。Prompt、Dify/Coze 和项目案例可按来源密度放入对应专题题库，不为凑分类而重复设题。

每个大专题先建立完整题目目录，再按来源与知识点逐题扩写。题量由有效、去重后的知识点决定，不以堆数量作为完成标准；“大模型基础、训练、推理、RAG、Python”应有明显更完整的覆盖，不能用数道概括题替代。

## 4. 单篇教材的最低结构

每篇基础教材按实际主题取舍，但需覆盖适用部分：

1. 学习目标、前置知识和关键词。
2. 从直觉到准确解释的概念定义；术语首次出现时给中文释义。
3. 逐步机制/数据流：说明输入、关键中间量、计算或决策过程、输出，以及为什么这样设计。
4. 关键公式：解释每个变量、张量/维度含义和公式用途；适合时用小型数值例子走一遍，不能只贴公式。
5. 可运行或可手算的例子：说明输入、预期结果和常见错误；代码要简洁并与解释一致。
6. 易混概念比较表、适用场景、优缺点、限制和失败模式。
7. 练习与答案/检查点，帮助学习者自测是否真正理解。
8. 与相邻主题的双链，以及实际核读的参考资料列表。

并非每个主题都有数学公式或代码；无必要时不强行添加。涉及版本化 SDK/API 的具体代码需标出版本/核对提醒。

## 5. 单道面试题的最低结构

每道重要问题应包括：

1. **面试简答**：先给出可在约 30–60 秒表达的直接答案，不用空泛套话。
2. **展开原理**：按步骤解释机制、关键概念、公式或流程，并指出适用前提。
3. **追问与回答**：至少给出有代表性的深入追问及答案，不能只有追问标题。
4. **易错点/对比**：说明常见错误说法、容易混淆的概念，以及正确边界。
5. **场景题或验证方法**：说明落到项目时怎样选择、测量或排查；没有真实项目经历时，明确区分练习案例和生产经验。

题目以概念掌握为中心，用原创问法表达；重复问题合并，但不能因为去重而丢失不同考点。回答必须与教材一致、信息足够完整，不把“关键词列表”当作答案。

## 6. 来源追踪与资料核验

- 每篇笔记列出实际使用的资料标题，尽可能标明文件名/课程章节；必要时区分“直接核读”“只用于发现主题”“待 OCR/人工查看”。
- 先抽取目录和文件级清单，再按专题阅读资料正文；去重以内容为准，不只按文件名判断。
- 当不同资料的表述或版本不一致时，解释差异或标记待核实，不静默拼接。
- 当前索引已有无法提取文字的 PDF（例如 AgentSkill 指南）；未完成 OCR/人工复核前，不将其作为论据。
- 对 478 路径盘点保持原口径，不宣称全部已审完。若进一步核查发现范围外的非 AI 内容，应排除并更新索引范围说明。

## 7. 验收标准

- 从 Python/机器学习基础到 AI 应用专题有清楚的学习顺序和双链导航。
- 对每篇抽样检查：是否有可理解的定义、机制步骤、例子、易错点和来源；重要公式/代码是否解释正确。
- 对每个大专题抽样检查多道题：都有直接答案、深入解释、追问答案和易错点，而不是概览式一句话。
- Python 语法范围与现有 `Python基础与AI应用` 及来源课程对照；已有覆盖保留，缺项补全，不另造重复摘要。
- 每个已核读专题明确列出资料来源和核读状态；未读、扫描件和版本不确定内容不伪装为已验证。
- 新增/改写笔记满足模板的 YAML 属性，并保持 `public + published`；Obsidian 双链目标存在。
- 更新 AI 知识地图和资料整编索引，让学习者能区分基础教材、题库、资料覆盖和待核验来源。
- 最终单独说明已完成的专题、尚未完成的专题和无法核读的来源；不以“整个资料库完成”夸大部分交付。

## 8. 分批实施顺序

1. 核对现有 Python、AI 原理、面试笔记和已盘点来源，创建逐专题来源/覆盖检查表；保留已有内容和未提交用户改动。
2. 深化 Python 与机器学习/深度学习前置知识，并建立对应基础/面试链接。
3. 深化大模型基础、训练微调与对齐、推理部署，并逐题展开对应题库。
4. 深化 RAG、Prompt、LangChain、LangGraph、Agent/MCP/Skill。
5. 深化幻觉评测、多模态、Dify/Coze 与案例题；OCR/不可读资料先标注或单独请求处理，不凭标题补写。
6. 更新导航、索引和来源状态，做 Frontmatter、内部链接、重复内容和知识深度抽查；最后明确报告边界。

分批不代表每阶段都要等待用户逐题审批；在总规范和实施计划获批后，按此顺序连续整理并定期报告进展。
