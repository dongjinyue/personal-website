# Obsidian 知识库网站集成设计

## 1. 目标

在 MY SPACE 中增加一个以个人检索为优先、同时支持选择性公开的知识库。Obsidian 继续作为唯一编辑后台，服务器上的 Markdown 文件继续作为权威数据源；网站只负责安全读取、解析、搜索和展示。

第一版不提供网站端编辑、普通用户注册、会员、付费或数据库同步。

## 2. 已确认的产品选择

- 顶部导航名称为“知识库”。
- 知识库首页采用“检索工作台”：桌面左侧是分类和标签索引，右侧是搜索、筛选与笔记列表；手机端收为单列。
- 默认展示全部可访问笔记，按最近更新时间倒序排列。
- 全文搜索覆盖标题、标签和正文，并高亮匹配词、展示命中片段。
- 搜索词、分类、标签、排序和页码写入 URL（网址）参数。
- 每页展示 12 篇，使用明确页码、上一页和下一页。
- 分类来自 `notes` 下第一层文件夹；标签来自 Frontmatter（文章属性）。
- 笔记列表展示标题、摘要、标签、分类、更新时间和权限状态。
- 摘要优先使用可选的 `description`，缺失时从正文自动生成。
- 管理员默认看到公开、私密和草稿，并用文字徽标区分；游客只看到公开且已发布的笔记。
- 详情页以正文为主，桌面右侧显示文章目录，手机端隐藏目录。
- 支持反向链接、上一篇和下一篇。
- 支持代码语法高亮、语言名称和复制按钮。
- 图片保持原比例并支持查看大图，但必须经过服务端权限接口。
- 网站不展示私密笔记的占位标题。

## 3. 架构方案

### 3.1 方案比较

采用“运行时读取 + Git 提交感知缓存”：

1. Next.js 在服务器运行时读取知识库当前提交中的 Git 对象，不直接遍历可能正在切换的工作区文件。
2. 以知识库当前 Git 提交哈希作为缓存版本。
3. 同一提交只扫描和解析一次；提交变化后自动重建内存索引。
4. 网站不需要因知识库更新而重新构建或重启。

没有采用以下方案：

- 同步脚本预生成索引：性能更高，但会把 Git 同步和网站结构耦合，第一版没有必要。
- 将元数据写入 Supabase：便于未来扩展，但会产生第二个数据源并增加一致性成本。

### 3.2 模块边界

`lib/knowledge/` 是唯一的数据读取层，计划拆分为：

- 配置：解析并校验知识库根目录。
- 扫描：只遍历 `notes` 下的 Markdown 和 `attachments` 下允许的图片。
- Frontmatter 解析：将文件转换成明确的笔记元数据。
- Markdown 渲染：处理标准 Markdown 与受支持的 Obsidian 语法。
- 索引：生成全文搜索文本、分类、标签、目录、出链和反向链接。
- 权限：根据服务端管理员身份产生当前请求可访问的数据集合。
- Repository（数据访问层）：为列表、详情、图片和状态页提供稳定接口。

页面和组件不能直接访问文件系统，也不能自行复制权限过滤逻辑。

每次建立索引时先固定一个完整提交哈希，再从该提交的 Git tree（文件树）读取 Markdown blob（文件对象）。即使定时同步恰好更新工作区，本次解析仍只会看到一个完整版本，不会混合新旧文件。

## 4. 数据约定

### 4.1 Frontmatter

每篇笔记必填：

```yaml
title:
slug:
visibility: public | private
status: published | draft
tags: []
created_at:
updated_at:
```

可选：

```yaml
description:
```

规则：

- `slug` 全库唯一，并限制为安全的网址片段。
- 日期必须可解析，且 `updated_at` 不早于 `created_at`。
- 分类取 Markdown 文件相对 `notes` 的第一层目录。
- 未知字段可以保留在源文件，但第一版不会自动展示。
- 单篇笔记校验失败不会阻断其他有效笔记。

### 4.2 支持的内容

- 标准 Markdown 标题、段落、列表、链接、图片和引用。
- GitHub Flavored Markdown（GitHub 风格 Markdown）的表格与任务列表。
- 围栏代码块、语法高亮、语言标签和复制按钮。
- `[[目标]]`、`[[目标|别名]]` 和 `![[图片.png]]`。
- 常用 Obsidian Callout（提示块），包括说明、提示、警告和错误。

不允许原始 HTML。外部链接协议使用允许列表，拒绝 `javascript:` 等危险协议。

### 4.3 图片

- 图片必须位于知识库的 `attachments` 目录。
- 第一版允许 JPG、JPEG、PNG、WebP、GIF 和 AVIF。
- 第一版不直接展示 SVG，避免其中携带活动内容。
- 图片请求必须携带所属笔记的安全标识；服务端先验证该笔记可见性，再解析附件路径。
- 解析后的真实路径必须仍位于 `attachments` 内，拒绝 `..`、绝对路径和符号链接逃逸。

## 5. 权限与隐私

权限规则在任何内容解析结果进入响应前执行：

| 访问者 | public + published | private + published | public/private + draft |
|---|---:|---:|---:|
| 游客 | 可访问 | 不可访问 | 不可访问 |
| 管理员 | 可访问 | 可访问 | 可访问 |

- 管理员身份沿用 `lib/auth/admin.ts` 的服务端校验。
- 游客的列表、搜索、标签计数、分类计数、反向链接和相邻笔记只基于游客可访问集合。
- 404（未找到）响应不区分“私密笔记存在”和“笔记不存在”。
- 私密笔记的标题、摘要、标签、正文、图片路径和链接关系不能发送到游客浏览器。
- 管理员状态页读取错误信息前必须调用 `requireAdmin()`。

## 6. 页面与交互

### 6.1 顶部导航

在现有“首页、AI 新闻、项目、工具集”之后增加“知识库”。知识库路由使用 `aria-current="page"` 表达当前分区，并沿用现有桌面、手机和键盘行为。

### 6.2 `/knowledge`

- 页面标题、笔记总数和搜索框。
- 桌面左侧显示“全部笔记”、文件夹分类和常用标签；手机端在正文之前显示可展开筛选区。
- 搜索覆盖标题、标签和纯文本正文，中文按规范化后的连续文本匹配。
- 排序支持“最近更新、最早创建、标题”。
- 管理员额外拥有状态筛选，并能看到“公开”“仅管理员”“草稿”徽标。
- 空知识库与无搜索结果使用不同状态；无搜索结果提供清除筛选操作。
- 列表卡片展示标题、摘要、分类、标签、更新时间和权限状态。
- 每页 12 篇，过滤条件改变后回到第 1 页，越界页码由服务端修正。

### 6.3 `/knowledge/[slug]`

- 展示面包屑、标题、权限状态、更新时间、预计阅读时间和正文。
- 桌面右侧提供随文章滚动的目录；窄屏不显示目录，避免挤压正文。
- 代码块提供可访问的复制按钮，成功与失败都使用可读状态文本。
- 内部链接跳转到知识库详情；无效链接对管理员标记“链接不存在”，对游客退化为普通文字。
- 文末显示当前访问者有权查看的反向链接、上一篇和下一篇。
- 图片点击后使用应用内查看层展示大图，支持 Escape 关闭、焦点恢复和窄屏安全边距。

### 6.4 `/admin/knowledge`

这是只读状态页，不是编辑器。显示：

- 当前知识库 Git 短哈希和最近成功解析时间。
- 有效笔记总数及公开、私密、草稿数量。
- 文件级校验错误，包含相对路径和可操作原因，但不展示正文。
- 重新读取入口仅刷新网站缓存，不执行 Git 拉取。

## 7. 缓存与一致性

- 默认知识库路径为 `/home/ubuntu/content/obsidian-vault`。
- 本地开发和测试可通过 `OBSIDIAN_VAULT_DIR` 覆盖路径。
- 服务端读取当前 Git 提交哈希；哈希未变化时复用已完成的解析结果。
- Markdown 和图片都从固定提交的 Git 对象读取，避免与定时更新发生竞态。
- 新版本解析成功后原子替换缓存。
- 新版本解析过程中仍提供最后一次成功结果。
- 单篇无效笔记进入管理员错误列表，其余有效笔记继续服务。
- 根目录不可用或整库无法读取时返回稳定错误状态，不回退为示例内容。

## 8. 视觉方向

知识库延续 DESIGN.md 的“个人工作台中的索引卡与版本注记”：

- 使用现有浅灰蓝背景、白色内容面、深蓝灰正文和钴蓝强调色。
- 分类与标签承担索引功能，不使用装饰性编号。
- 详情正文可以使用现有宋体展示字体呈现标题，正文保持中文友好的无衬线字体和舒展行高。
- 页面层级主要依靠间距、细边框和背景，不使用通用博客的大幅 Hero（首屏主视觉）或霓虹渐变。
- 主要视觉特征是“左侧知识索引 + 右侧检索结果”，与新闻简报结构区分。
- 只为筛选、复制和图片查看提供必要反馈；在 `prefers-reduced-motion` 下取消非必要位移。

该功能会把长期视觉规则补充到 `DESIGN.md`，并把导航、权限、搜索、详情和状态行为补充到 `UX-CONTRACT.md`。

## 9. 异常处理

- 知识库为空：说明如何在 Obsidian 新建并同步第一篇笔记。
- 无搜索结果：保留搜索词，显示清除筛选按钮。
- Frontmatter 错误：游客忽略该笔记；管理员状态页显示字段级原因。
- 内部链接失效：管理员看到提示，游客看到普通文字。
- 图片缺失：保留稳定图片区并显示替代文本，不让页面布局跳动。
- 知识库暂时不可读：返回通用错误，不输出服务器绝对路径。
- Git 正在更新：读取一致版本或最后一次成功缓存，避免读取半更新状态。

## 10. 测试与验收

### 10.1 自动化测试

- Frontmatter 合法、缺失、类型错误、重复 slug 和非法日期。
- public/private 与 published/draft 的完整权限组合。
- 游客的搜索、计数、反向链接和相邻笔记中不存在私密数据。
- Markdown 表格、任务列表、Callout、代码块和目录生成。
- Obsidian 双向链接、别名、图片嵌入和失效链接。
- 中文全文搜索、命中片段、高亮、分类、标签、排序和分页。
- 图片扩展名、路径穿越、绝对路径、符号链接逃逸和无权访问。
- Git 提交变化后的缓存更新，以及无变化时的缓存复用。

### 10.2 项目检查

- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- Next.js 16 相关实现以本项目 `node_modules/next/dist/docs/` 为依据。

### 10.3 浏览器验收

- 分别以游客与管理员检查列表、搜索、详情、图片和 404。
- 检查加载、空数据、无结果、错误和长文章。
- 检查键盘焦点、复制状态、图片查看层和返回焦点。
- 检查 1440、1024、768 和 390px，不出现意外横向滚动。
- 检查 `prefers-reduced-motion`、200% 缩放和可见焦点。

## 11. 实施边界

本设计包含知识库读取、展示、搜索、权限和只读状态页。以下内容明确不在第一版：

- 网站端创建、编辑或删除笔记。
- 普通用户注册、成员权限、付费内容。
- Supabase 笔记表、全文搜索扩展或向量检索。
- 评论、点赞、阅读统计和内容推荐算法。
- 自动 Git 推送、在线文件管理或附件上传。
